# Verification responsibilities

The maintained application route is `MeniscusAnnotatorLib` plus the native Slicer integration script. Input preparation remains the responsibility of the separate dataset-preparation project; its private audit is not part of this application.

Technical checks establish identity, file integrity and native geometry. They do not establish anatomical correctness. Jeff's approval is the assigned annotator's own approval, not an independent second-reader assessment. Passing synthetic tests does not release the 250-case batch.

## Automated development checks

Run the core tests with the pinned development dependencies. `tests/slicer_workflow.py` must additionally run **inside Slicer 5.12.4 r34645** with the local module directory on its additional-module paths. It drives the native Segment Editor effects through slice-view events and compares full arrays, rather than testing only helper functions.

Use `MENISCUS_TEST_OUTPUT` to select a local test-results directory, `MENISCUS_REPO` if executing through `exec`, and optionally `MENISCUS_TEST_KEEP_OPEN=1` for visual inspection. All examples generated by this script are synthetic. The script writes `slicer-workflow.json` with each executed assertion and a screenshot of the actual application. A script that stops at a failure has **not** exercised subsequent assertions.

Required native integration coverage:

- Axis-aligned and oblique sagittal grids; varying extents/slice counts; anisotropic spacing.
- Known native voxel paint, exact acquired-slice isolation, medial/lateral replacement, erase and undo/redo.
- Contour drawing and independent uncertainty; no undocumented training class.
- Review invalidation on edits, including undo/redo; explicit review of empty slices.
- Save/reopen exact arrays and original geometry; independent NIfTI reader checks.
- Approval gates, approved snapshot immutability and a new draft after editing.
- Approved-only export ZIP, metadata/hashes and independent reopen of exported masks.

Core fault coverage includes transformed/missing geometry, unknown units, changed source, permission/disk-full simulations, incomplete interrupted checkpoints, corrupt recovery, duplicate writer sessions and prediction-free mode. Record precisely which are executed in the test report.

## Windows release acceptance — must run on Windows

No macOS/Rosetta result verifies Windows support. A successful build does not verify the installer. Record installer SHA256, app version, exact Windows edition/build, display scaling, screen resolution, hardware and tester for every Windows release candidate.

1. Install the actual installer on a clean supported Windows machine. No Python, Slicer or development tools may be preinstalled. Retain installation evidence and required licence files.
2. Disconnect network access. Launch from Start menu; open the committed synthetic package using the folder picker. Confirm no runtime download and no terminal requirement.
3. Test paths with spaces and Unicode in dataset, work and results folders. Exercise the documented long-path limit; confirm a clear error instead of partial output.
4. At 100%, 150% and 200% display scaling, resize on a normal laptop screen. Inspect labels, tools, notes, dialogs, canvas and bottom controls for clipping and readable contrast. Collapse the case panel.
5. Test physical mouse scroll, single-step controls, shortcut help, pan, zoom, window/level, reset, opacity and outline/fill. Type shortcut letters in notes and confirm editing/navigation does not trigger.
6. On the oblique fixture, draw and erase on a known acquired plane and verify only its native K index changes. Test Undo/Redo. Inspect anatomical orientation labels and native 1..N slice numbering.
7. Mark empty and nonempty slices reviewed, edit a reviewed slice and confirm rechecking. Test next unreviewed and attention navigation. Attempt approval with incomplete review, unchecked compartments and unresolved attention.
8. Save, close, reopen and resume the case/slice. Kill the application after an autosave; recover the saved checkpoint and disclose that unsaved strokes and undo history need not survive.
9. Launch a second application instance and try to open the same case for editing. It must refuse the second writer. Close the first instance and verify lock release.
10. Approve a synthetic practice case deliberately. Edit it, save a new draft, and prove the approved version still exists and exports unchanged.
11. Export selected approved cases and all approved cases. Unfinished work must be excluded. Use Show exported file; reopen results with the independent checker. Ensure MRI images are absent from the ZIP.
12. Reconnect a moved dataset, then try one with changed bytes and identical names. Only the unchanged scan identity may resume.
13. Exercise a read-only destination, insufficient free space and corrupted checkpoint; verify actionable errors preserve existing work and avoid normal-interface stack traces.
14. Close/reopen offline, uninstall/reinstall without deleting the work folder, and confirm saved-work persistence.

The actual downstream training-loader test is a separate integration requirement owned by the training pipeline. Do not mark it passed from a nibabel or Slicer reopen.

## Permitted practice and batch gate

Use real development/practice scans only when explicitly provided with permission. Do not use protected final-test cases for interface tuning. Keep real identities, images, results and private logs outside Git. Before any release for all cases, exercise import → native edit → save → reopen → review → approve → export in the actual application and check saved outputs independently. Resolve the anatomical-protocol status and final uncertainty policy with the study team before research approval.
